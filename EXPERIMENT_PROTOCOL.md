# Протокол эксперимента

## 1. Задача

Проверяется, насколько Effective Rank полезен для выбора девяти внутренних
ширин ResNet-20 по сравнению с `l1_weight`, `taylor`, `uniform` и `random`.

Основная одношаговая сетка изолирует качество архитектуры: все компактные
модели обучаются с нуля. Перенос конкретных каналов и `finetune` рассматриваются
отдельно и не смешиваются с этой сеткой.

## 2. Модель

Полные внутренние ширины:

```text
[16, 16, 16, 32, 32, 32, 64, 64, 64]
```

Меняется только ширина `M` внутри остаточного блока:

```text
C_in -> Conv1 -> M -> Conv2 -> C_out
```

Входная и выходная ширины сохраняются, поэтому residual-связи остаются
совместимыми.

## 3. Данные и запрет утечки test

CIFAR-10 разделяется детерминированно:

- 45 000 изображений — обучение;
- 5 000 изображений — проверка, выбор эпохи и расчёт критериев;
- 10 000 официальных test-изображений — только финальная оценка.

Test не участвует в выборе ширин, расчёте Effective Rank, `l1_weight`,
`taylor` или лучшего checkpoint.

## 4. Методы выбора ширин

### Effective Rank

Для выхода `Conv1 -> BN -> ReLU` каждого из девяти блоков рассчитываются:

1. `erank_per_image` — ранг отдельно для каждого изображения и среднее по
   проверочной выборке;
2. `erank_pooled` — ранг общей центрированной статистики активаций;
3. `erank_weight` — ранг развёрнутой матрицы весов `Conv1`.

Effective Rank вычисляется как экспонента энтропии нормированных сингулярных
значений. Он задаёт относительное распределение бюджета, а не готовое число
каналов.

### Классические критерии

- `l1_weight` — сумма модулей весов фильтра;
- `taylor` — модуль произведения активации на градиент ошибки.

Оценки нормируются внутри слоя. Каналы удаляются группами по два там, где
отношение важности к экономии параметров минимально.

### Контрольные методы

- `uniform` — приблизительно равномерное относительное уменьшение групп;
- `random` — случайный профиль девяти ширин при заданном бюджете параметров.

## 5. Бюджеты

Используются:

```text
p090 p080 p070 p060 p050 p040 p030
```

Метка показывает сохраняемую долю параметров полной модели. Реальное число
параметров рассчитывается точно, поэтому небольшое отклонение от целевого
процента допустимо.

Ширины ERank- и `random`-моделей округляются до чётных значений, имеют минимум
4 и не превышают ширину полной модели. `uniform` подбирается по целочисленной
сетке. Для `l1_weight` и `taylor` используется шаг два канала.

## 6. Виды случайности

В протоколе не смешиваются:

- `train_seed` — начальные веса и порядок данных;
- `architecture_seed` — случайный профиль ширин;
- `mask_seed` — будущий случайный выбор конкретных переносимых каналов.

Основная сетка использует `train_seed=1`. Для каждого бюджета `random`
использует десять `architecture_seed`: 1001–1010. Следовательно, разброс
`random` описывает различие архитектур.

Отдельный эксперимент `p060` использует `train_seed=1,2,3` для фиксированных
архитектур и описывает разброс обучения.

## 7. Объединение совпадающих архитектур

Если два критерия дают одинаковые девять ширин, сеть обучается один раз. В
манифесте представитель записывается в `method`, а все эквивалентные названия —
в `aliases`.

В завершённой сетке:

- 106 физических запусков;
- 112 логических точек методов;
- 106 файлов `history.json`;
- 106 файлов `test.json`.

## 8. Протокол обучения

| Параметр | Значение |
|---|---:|
| Эпохи | 160 |
| Оптимизатор | SGD с momentum и Nesterov |
| Начальный `learning rate` | 0,1 |
| Scheduler | CosineAnnealing |
| Momentum | 0,9 |
| Weight decay | 0,0005 |
| Batch size | 128 |
| AMP | включён на CUDA |
| Лучший checkpoint | максимум validation accuracy |

Все методы одного бюджета получают одинаковый протокол. Ни один метод не
получает дополнительного дообучения в основной сетке.

## 9. Метрики

Основная метрика качества — accuracy на официальной test-выборке. Также
сохраняются loss и validation-история.

Размер оценивается точным числом обучаемых параметров. Вычислительная стоимость
оценивается MACs на одно изображение. Аналитический расчёт MACs совпадает с
hook-счётчиком `benchmark.py` для полной модели:

```text
40 813 184 MACs на изображение
5 224 087 552 MACs на batch из 128 изображений
```

В MACs входят `Conv2d` и финальный `Linear`. Batch normalization, активации,
сложения residual-связей и pooling не учитываются, как и в существующем
benchmark-счётчике.

## 10. Анализ результатов

`grid_analysis.py`:

1. проверяет наличие всех результатов;
2. сверяет ширины и число параметров;
3. рассчитывает MACs;
4. разворачивает `aliases` в логические точки;
5. считает среднее, отклонение, минимум и максимум для `random`;
6. определяет лидера каждого бюджета;
7. сохраняет JSON, CSV и Markdown.

Графики строятся только из `reports/data/grid_results_v09.json`. Это позволяет
полностью воспроизвести отчёт без весов моделей и CIFAR-10.

## 11. Правила интерпретации

- Разница одного `train_seed` не считается доказательством статистического
  превосходства, если она сопоставима с наблюдаемым разбросом обучения.
- Разброс `random` нельзя называть разбросом обучения: меняются архитектуры.
- Методы при одинаковом числе параметров могут иметь разное число MACs.
- Локальная чувствительность одного блока и качество целой обученной с нуля
  архитектуры отвечают на разные вопросы.
- Test используется для итогового сравнения после фиксации сетки, а не для
  настройки архитектуры.

## 12. Следующие этапы

1. Эксперимент переноса каналов при фиксированных ширинах: L1-перенос,
   случайная маска и другие заранее определённые правила.
2. Повторные `train_seed` для выбранных репрезентативных точек кривых.
3. Итеративный поиск, где критерий пересчитывается после каждого шага сужения.
4. Сопоставление одношагового и итеративного поиска при одинаковых бюджетах и
   протоколе обучения.

Команды полного воспроизведения находятся в `README.md` и
`V08_GRID_RUNBOOK.md`.
